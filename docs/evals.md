# 质量与评测

M0 将确定性正确性和模型质量分开验证。确定性门槛必须在每次变更中通过；真实模型评测暂不进入默认 CI。

## 四层验证

### 1. 领域单元测试

使用 Vitest 覆盖：

- Zod Schema 拒绝非法结构；
- Evidence Offset 与 Hash；
- Story Map 唯一 ID、参与人物和边引用；
- Anchor 状态与 fail-closed；
- Worldline 创建前必须接受 Impact Plan；
- 幂等键与父/兄弟世界线隔离。

### 2. 合约测试

使用固定模型响应样本验证：

- 合法响应可以形成候选 Artifact；
- 非法 JSON、缺证据和悬空引用被拒绝；
- 修复最多一次，失败后不留下半提交状态；
- Prompt / Schema 版本变化必须显式迁移。

### 3. 浏览器 E2E

使用 Playwright 和公开夹具覆盖：

```text
首页 → 基准故事 → 选择关键事件 → 查看证据
→ 生成涟漪预览 → 确认 → 创建世界线 → 刷新恢复
```

默认只运行 Chromium；增加浏览器矩阵前先证明存在兼容性需求。

### 4. Live Model Eval

真实模型接入后提供人工触发的 `npm run eval:live`，但不在每次 PR 中调用。报告至少记录：模型、Prompt 版本、输入 Hash、事件召回、证据有效率、因果认可率、Anchor 判断和相对上次退化项。

## `ripple-001` 最低质量门槛

- 核心人物识别率：100%；
- 人工标记关键事件召回率：至少 80%；
- 关键事件证据有效率：100%；
- 主要因果边人工认可率：至少 70%；
- 预设分歧的一级影响召回率：100%；
- 明确不兼容 Anchor 必须被拦截；
- 续写不得恢复已被世界线删除的事实。

这些是 M0 工程基线，不是长期产品 KPI。

## 分享前检查

1. `npm run lint`；
2. `npm run typecheck`；
3. `npm test`；
4. `npm run test:e2e`；
5. `npm run build`；
6. 人工检查首页、故事地图、证据抽屉、Ripple Preview 和刷新恢复；
7. 确认截图、日志、数据库和夹具不含真实用户作品或密钥。
