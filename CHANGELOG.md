- M1 baseline runner 支持可选的 `NOVELRIPPLE_BENCH_ROOT`：该目录的 realpath 作为额外 private 根，manifest 必须为 `visibility: private` 且 Source 留在该根内；未设置或为空时行为不变。Optional `NOVELRIPPLE_BENCH_ROOT` adds an extra private benchmark root; manifests must be private and sources must stay inside it.

- 抽取/补抽候选新增 `kind: "individual" | "group"`；只要具体个体在本片段事件中参与（行动、说话、被行动波及或在场），即使无名、只短暂出现或处于边缘也列为 `individual`，边缘人物用 `role: "minor"`；固定两人小组合可作为一条 `individual`，模糊人群/复数集体仍为 `group`。组装时确定性丢弃群体、家族、机构候选并从事件参与者中移除，仅当事件只剩群体时保留一个群体作为最小例外。Candidate characters now carry `kind`; any specific individual who takes part in a chunk event is an `individual` even when unnamed, brief or peripheral, with `role: "minor"` for peripheral ones; a fixed pair acting as a unit may be one `individual`, and vague crowds remain `group`. Assembly deterministically drops groups, households and institutions from the pool and event participants, keeping one group only when an event would otherwise have no participant.
- 人名候选新增确定性垃圾过滤（多数出现后接 了/着/过/地/得、姓氏后虚词碎片、常见非人名 STOP_WORDS）和非姓氏昵称规则（`阿/小/老` + 单字或 ASCII 字母，出现 ≥2 次）。Deterministic junk filtering and a non-surname nickname rule were added to name hints.
- 事件粒度改为场景/情节节拍级（通常每 600–1000 字一个），同一连续场景或对话不拆条；因果边只为直接、重要关系保留，约每事件至多一条出边。Event granularity is now scene/plot-beat level (roughly one per 600–1000 characters) and causal edges are restricted to direct, important relations.
- 新增 `story-map-merge.v2`：除跨块重复外，还合并相邻块把同一场景拆得更细的事件，并用 `duplicateEndingGroups` 合并在同一人物/故事主线上得到同一结果的结局候选；不同人物的命运即使相似也不算重复。New merge v2 also folds finer-grained adjacent scene events and duplicate ending candidates for the same character or storyline; different characters' fates are never duplicates.
- 人名轮新增 `rejectedCandidateIds`：每个候选必须恰好归入一个人物的 `mergedFrom` 或列入拒绝列表一次；只允许拒绝漏网的群体/家族/机构与只评论的作者叙事者，具体人物即使只短暂出现、无名、边缘或不确定也必须合并为 `role: "minor"`。服务端拒绝对参与事件的具体个体使用拒绝列表。被拒候选从人物与事件参与者中移除，事件只剩被拒参与者时保留第一个作为人物。The names pass now requires `rejectedCandidateIds`: every candidate must be merged once or rejected once; only slipped-through groups/households/institutions and comment-only narrators may be rejected, while brief, unnamed, peripheral or uncertain individuals must merge as `role: "minor"`. The server refuses to reject an individual who participates in an event. Rejected candidates are removed from characters and participants, keeping one only when an event would otherwise be empty.
- 全书合并 prompt 新增 `<granularity_hint>`（核心文本字符数与目标事件范围，下限 3）；事件明显超出上限时折叠相邻同场景/更细节拍，范围内只合并真正重复，绝不合并不同场景或转折点。The merge prompt now includes a `<granularity_hint>` with core text length and a target event range (lower bound 3); clearly over-budget lists fold adjacent same-scene/finer beats, within-range lists merge only true duplicates, and different scenes or turning points are never merged.
- `story-map-chunk.v2` / `story-map-glean.v2` 明确：只被提到、回忆或谈论、并未在本片段事件中参与的人不得列为人物；参与事件的无名、短暂或边缘个体仍应列为 `individual` 并用 `role: "minor"`。Chunk/glean v2 now explicitly exclude people who are only mentioned, remembered or talked about without taking part in a chunk event, while unnamed, brief or peripheral participants stay `individual` with `role: "minor"`.
- 新增 `story-map-endings.v2`：只产出 1 个故事级结局；对每个结尾命运已定或被明确留白的角色（含已离场配角与主角/叙述者本人）各产出 1 个人物结局，不重复同一结果。New endings v2 emits one story-level ending and one ending for every character whose fate is resolved or explicitly left open, including departed supporting characters and the protagonist/narrator.
